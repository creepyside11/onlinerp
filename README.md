# RakCRMP

Меню поверх Online RP для Android. Красная круглая кнопка, меню с
функциями, ESP и координаты сверху экрана.

Код игры **не меняется**. В APK добавляется Frida gadget, а вся логика
живёт в JavaScript-агенте — его можно править без пересборки APK.

## Функции

| Функция | Как сделано | Состояние |
|---|---|---|
| Бессмертие | удержание здоровья через поле `CPed+0x6AC` | готово |
| Спидхак | масштабирование `CTimer::UpdateVariables`, 1.0–5.0x | готово |
| Телепорт по метке | `CEntity::Teleport` + блип из `CRadar::ms_RadarTrace` | готово |
| Запомнить/вернуться | сохранение точки в памяти агента | готово |
| Бессмертие авто | `CVehicle::CanVehicleBeDamaged` → всегда «нет» | готово |
| Вечный двигатель | периодический `CVehicle::Fix` | готово |
| ESP: люди / машины | пулы `CPools` + `CalcScreenCoors` | готово |
| BOX | рамка с подписью и дистанцией | готово |
| Координаты | плашка X/Y/Z сверху по центру | готово |

## Как это устроено

Ключевое везение проекта: `libGame.so` в этом клиенте **не обрезан** —
16 809 экспортированных функций с полными C++ именами. Поэтому всё
делается через вызовы движка по имени, а не через поиск адресов наугад.

```
agent/
  main.js              точка входа: ждём Activity, ждём движок, крутим цикл
  core/
    symbols.js         имена функций и смещения полей
    game.js            обёртки над движком (позиция, телепорт, пулы)
    log.js             лог в logcat с меткой RakCRMP
  ui/
    theme.js           цвета и размеры в dp
    draw.js            примитивы Canvas
    overlay.js         сам View: кнопка, меню, касания
  modules/             по модулю на функцию меню
build/
  bundle.py            склеивает agent/ в один файл (без npm)
  smoke.js             прогон агента без телефона
  patch_apk.py         вставляет gadget в APK и подписывает
```

Меню — обычный `android.view.View`, добавленный в decor view той же
Activity. Поэтому не нужно разрешение «поверх других приложений», и
касания вне кнопок уходят в игру как обычно.

## Скачать

Готовая сборка: **[RakCRMP.apk](https://github.com/creepyside11/onlinerp/releases/download/latest/RakCRMP.apk)**
(191 МБ, подписана, V3).

Ссылка всегда ведёт на последнюю удачную сборку — релиз `latest`
перезаписывается автоматически.

## Сборка

Всё в GitHub Actions, локально ничего не нужно:

1. Положить исходный APK в релиз с тегом `base` (файл
   `onlinerp_launcher.apk`).
2. Actions → `build-apk` → Run workflow.
3. Забрать `RakCRMP.apk` из артефактов.

Свой APK можно подставить через поле `apk_url` при запуске.

Локальная сборка тоже возможна, нужны `patchelf`, `zipalign`, `apksigner`:

```bash
python3 build/bundle.py
node build/smoke.js
python3 build/patch_apk.py --apk base.apk --gadget frida-gadget.so \
  --script build/agent.js --keystore release.keystore --storepass rakcrmp123 \
  --out RakCRMP.apk
```

## Установка

Сначала освободи место: APK занимает 191 МБ, плюс столько же уйдёт на
распаковку при установке. В `Download` лежат два старых APK на 250 МБ —
их можно удалить, они больше не нужны.

1. Удалить оригинальный клиент — подпись другая, иначе Android откажется
   ставить обновление. Аккаунт от этого не страдает: он на сервере.
2. Установить `RakCRMP.apk`.
3. Запустить игру. Через несколько секунд появится красная кнопка.

Если кнопки нет — смотреть лог:

```bash
adb logcat -s RakCRMP
```

Проверить, что gadget вообще загрузился:

```bash
adb logcat | grep -i frida
```

## Что проверено, а что нет

Сборка в CI проверяется автоматически: gadget подключён к `libClient.so`
(`readelf -d` показывает `NEEDED libgadget.so`), скрипт и конфиг лежат в
`lib/arm64-v8a`, подпись V3 на месте.

Дымовой прогон агента (заглушки Frida, без телефона) проверяет загрузку
бандла, привязку к Activity, регистрацию View, отрисовку меню и касания.

**На живом устройстве агент не запускался** — возможности проверить нет.
Отдельного внимания требует:

* **Спидхак.** Frida отдаёт float-регистры по-разному в разных версиях.
  Модуль сам определяет доступный регистр и, если не находит, честно
  выключается с записью в лог, а не портит игру.
* **Смещение здоровья** `0x6AC`. Найдено статически в конструкторе `CPed`.
  Перед записью значение проверяется: если в поле не похоже на здоровье,
  модуль не пишет. Ошибка в смещении не приведёт к порче памяти.

## Риски

Читы в онлайн-игре — это бан по правилам сервера. Тестировать лучше не на
основном аккаунте. ESP и телепорт заметны со стороны, бессмертие — тоже.
