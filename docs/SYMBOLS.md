## Смещения полей

### Здоровье и броня: `0x6AC` и `0x6B0`

В конструкторе `CPed` (`0x568634`) видно:

```
56871c: mov  w8, #0x42c80000      ; 100.0f
568720: add  x24, x19, #0x54c
568724: dup  v0.2s, w8            ; два float'а 100.0 подряд
56872c: str  d0, [x24, #0x160]    ; = [x19 + 0x6AC], 8 байт
```

Один 64-битный стор двух значений 100.0 — это здоровье и броня, они идут
парой. Отсюда `0x6AC` и `0x6B0`.

## Спидхак: почему именно `CTimer::UpdateVariables`

```
4a7fa8: fdiv s1, s0, s1
```

Функция читает единственный float из `s0` и не обращается к `x0`. Значит
`this` не используется и аргумент один — можно масштабировать время на
входе, не трогая остальную логику движка.

## Что осталось выяснить

* Точный размер пулов — сейчас перебираем 160 индексов; выход за границы

* Структура блипа в `ms_RadarTrace`: шаг 40 байт и тип метки по `0x2C`
  взяты по аналогии с GTA:SA, но на этом клиенте не сверялись.
